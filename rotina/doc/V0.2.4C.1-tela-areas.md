# V0.2.4C.1 — tela real de gestão de Áreas

Implementação da rota `/banco-mestre/areas` conforme V0.2.4A, usando a camada de dados B.1 e as actions autenticadas B.2. Somente listar, criar, renomear, ativar e desativar. Sem UI de prioridade, reorder, DELETE, mocks/seed, migration, RPC ou alteração de schema/RLS/Auth.

## Leitura e composição

A página usa Suspense com “Carregando áreas…” e leitura SSR por request. `createManagedAreasReader` cria o cliente Supabase server normal, exige getClaims/sub e constrói createAreaRepository; expõe somente listManagedAreas. `readManagedAreas` diferencia lista vazia de falha, reutilizando erros seguros e preservando controle de fluxo do Next.

`AreaManagement` recebe o resultado real por props. Reutiliza Button, Card, Badge, Input e Label. Mostra áreas ativas/inativas com indicação textual, lista vazia com “Criar primeira área”, orientação quando todas estão inativas e formulário de criação. Link “Gerenciar áreas” foi incluído na lista do Banco Mestre. Nenhuma cópia mutável de áreas foi adicionada ao provider.

## Gravação e estados

- Criação: nome obrigatório, UUID gerado uma vez por tentativa da instância do formulário, createMasterArea com id + nome. Retry de rede reutiliza o UUID. Após sucesso confirmado, mostra confirmação, solicita router.refresh e permite criar item ou iniciar outra criação explicitamente. Nunca acrescenta área fictícia à lista local.
- Renomeação: usa snapshot SSR integral, incluindo updatedAt original e sortPosition somente como metadados internos. Não há exposição visual desses campos. Erro mantém o nome digitado; nome vazio é rejeitado antes de enviar e a action repete validação no servidor.
- Desativação: confirmação explica que itens existentes continuam vinculados/disponíveis e novas associações ficam impedidas. Reativação envia active=true explícito. O booleano alvo é calculado a partir do estado SSR, não por toggle no servidor.
- Nome alterado e ainda não salvo bloqueia mudança de estado; salvar ou restaurar o nome é explícito. Isso impede perder rascunho por recarga após ativação/desativação.
- Envio mostra status acessível de salvamento, desabilita controles e possui trava síncrona contra envio duplicado. Nova gravação também fica bloqueada após sucesso até a leitura atualizada. Linhas usam chave id/updatedAt para inicializar somente snapshots novos; outras linhas preservam seus rascunhos quando seus dados não mudaram.
- Conflict mantém o formulário e bloqueia novo save com snapshot antigo, sem retry ou sobrescrita automática. Recarregar exige confirmação explícita de descarte dos rascunhos da tela.
- Unauthorized oferece “Entrar novamente”; Validation/NotFound/Unknown mostram mensagem segura e preservam o formulário. Rede não gera confirmação falsa; orientar conferir lista antes de repetir porque o commit pode ter ocorrido.

O proxy já cobre explicitamente POST de Server Action na rota exata, sem abrir outras rotas. Esta entrega não altera proxy, Auth ou actions. GET sem sessão continua protegido; a leitura SSR e as actions verificam novamente a sessão.
